# Changelog

- 2026-11-27
  - First version: an Alpine Linux image that runs Postfix as an inbound edge mail transfer agent (MTA). It accepts mail on port 25 for the domains in `POSTFIX_EDGE_DOMAINS`, from the networks in `POSTFIX_EDGE_MYNETWORKS` only, and delivers it over the Local Mail Transfer Protocol (LMTP) to the backend in `POSTFIX_EDGE_LMTP`. Found internally from backlog item 170.
  - It offers no authentication: authenticated submission on ports 465 and 587 stays with the mailbox server, which holds the accounts and checks their passwords. Postfix could reach those accounts only through Dovecot or Cyrus Simple Authentication and Security Layer (SASL), which most LMTP backends do not provide.
  - `POSTFIX_EDGE_TLS` takes Postfix's own `smtpd_tls_security_level` names: `may` (the default) offers STARTTLS, `encrypt` requires it, and `none` turns it off. With `may` or `encrypt` the entrypoint refuses to start without the certificate mounted at `/etc/postfix-edge/tls`, so TLS cannot be lost silently. Recipients are checked against the backend before they are accepted (`reject_unverified_recipient`), so the image sends no bounces for unknown users.
  - The image declares a health check, `postfix-edge-healthcheck`, which passes when Postfix's master process runs and port 25 completes an SMTP handshake, so Docker and Podman users see the service's state without Kubernetes; `--backend` also checks the LMTP backend, for readiness probes only. The image is built with Docker media types, because Podman ignores a health check in an image with OCI media types.
  - Continuous integration (CI) builds and smoke-tests the `linux/amd64` and `linux/arm64` images on native runners, then publishes both under one multi-architecture tag to the GitHub Container Registry, with a build provenance attestation, on every push to `main` and weekly. The weekly rebuild takes Alpine's package fixes.
  - The tags follow Postfix's release (`latest`, `<postfix version>`, `<postfix version>-<YYYYMMDD>`) with no version of the image's own, because the image only packages the upstream release, which Postfix versions.
